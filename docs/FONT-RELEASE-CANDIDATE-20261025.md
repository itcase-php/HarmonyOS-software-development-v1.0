## 本轮修复

1. **引擎用例不再依赖前台窗口。** 上次保存的设备报告实际为 10 项中 1 项通过、9 项错误；后续用例在获取前台 Ability 时失败，没有开始各自的转换。Core 与 JPEG 样例现在从应用上下文取得 `entry` 模块资源和缓存，不逐例获取前台 Ability。只有真实保存/分享选择器及源文件发布才请求 UI 上下文。全局发布选项也不再误使其他引擎用例要求前台窗口。此修改已通过模型回归与真实 SDK 编译，仍须真机重跑确认。
2. **关闭顺序保护正在运行的转换。** 主机失败回归确认旧代码可能在活动转换及输入清理完成前关闭 Native。现在先停止调度、等待交付、等待活动转换和输入清理，再确认当前作用域仍拥有运行时后关闭 Native。保存/分享中关闭、新窗口接管、转换清理期间接管均有回归。
3. **测试结果不以 HDC 返回 0 判定成功。** 新增保存报告解析器，检查总数、Failure、Error、Pass、Ignore 和结束标记。上次 1/9 报告被明确判失败，不能再写成完整设备验收通过。
4. **Windows 原生验证脚本可实际执行。** 修正 `findstr` 混用路径分隔符导致依赖检查找错文件的问题，使用与 CMake 配套的 CTest。新脚本已执行通过 26/26；保留 `/RTC1` 与 Debug CRT 检查。
5. **检查主包和测试包是否配套。** 静态包检查新增测试包核对：没有替换主引擎的 `libentry.so`，235 个共有原生库内容一致，新字体用例资源与源码一致。

此前实际字体使用关系、缺失字族和位置诊断、逐文件确认后保留原输入重试、图标字形保护等修改继续保留，见 [10 月 23 日代码记录](FONT-RELEASE-CANDIDATE-20261023.md)。源文件、字体名称和实际替换字体仍须据真实结果判断，不能据通用提示推断宋体/黑体安装失败。
