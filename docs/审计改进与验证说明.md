## 初始化与配置边界

`tools/generate-registry.cjs` 先执行现有配置设计检查，生成 metadata、Native 工厂/类型及 rawfile。编译进应用的 formatsSha256/matrixSha256 来自唯一编辑源 shared/format-registry；应用不会从待校验的 rawfile 自行读取期望摘要。

FormatRegistry.initialize 共享同一加载 Promise，完整验证成功后同时安装 formats/routes。失败或五秒超时不会发布半套缓存，后续调用可以重试；超时读取后来完成也不会覆盖新缓存。listFormats/listPlannedRoutes 返回深复制，未初始化的查询明确抛出 REGISTRY_NOT_INITIALIZED。

首页由 FoundationViewModel 在同一个五秒检测期限内加载配置和查询 Native；其他格式页面通过 RegistryUi 初始化。两者均使用 RawfileResources 显式 SDK 适配器。首页、格式浏览器、转换页及功能指南都处理加载错误；转换页初始化成功后才启用保真度选择。独立 Previewer 页面需要能够提供应用资源上下文；缺失时显示错误及重试入口，不用示例数据填充配置。

该机制校验本构建打包配置的完整性，不是数字签名、远程热更新或任意 JSON 的安全解码器。JSON 内容经过构建时设计检查且运行时字节摘要一致，才按声明类型解码。配置签名、动态更新、回滚和新版本原子切换仍属于后续工作。SDK 哈希能力不可用时明确失败。

## 调度、配置与测试约定

入队立即通知观察者，但状态保持 queued、progress=0。首次计划回调在 50ms 后，后续回调为 200ms；只有 queued/running 工作才保留计时器，全部暂停或结束时停止。advance 仍可显式调用供确定性检查使用；相同时间或较早时间不会重复累计活动耗时。Native 的异步执行和取消清理继续持有单并发槽直到 finally 完成。

TaskRuntime 封装时钟和超时调度，生产默认使用系统实现，测试每例使用独立 ManualTaskRuntime；无需真实等待 2/3.5/6 秒，也不共享 TaskStore 单例。测试名称中的清理操作对应现有 clearFinished()，没有另造 prune()。Native 调用继续使用原 execute()，没有新增 convert() 协议别名。

FidelitySettingsVM 同时携带质量、意图、最低等级、选项、摘要、路线可用性和交互禁用状态。子组件不修改 vm；页面在选择、确认、取消确认、任务状态和配置加载变化后发布新副本。展开/折叠仍由组件自行管理。
