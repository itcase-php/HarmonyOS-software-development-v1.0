## 回归原因及修复

上一轮将完整编译目录改成只保留摘要元数据，页面因此依赖 rawfile 和 SDK 哈希能力才能初始化。当前工作区又增加了手写降级目录：仅 PDF、JPEG、PNG、DOCX 四种格式和五条路线；任何资源加载或校验失败都会安装这份缩减目录并标记初始化成功。这直接造成显示数量从 18 变为 4，也丢失原有路线及其参数。

本次移除缩减目录，从原 shared/format-registry JSON 自动生成完整离线目录。没有编辑原始格式及路线定义，也没有把 planned 状态改成 available。完整目录立即可查询，首页计数、格式浏览器、转换页选择和功能指南不再等待原生检测；预览器缺少资源上下文、读资源失败或没有 SDK 哈希能力时，仍提供全部格式与演示规划。

保留 SHA-256、schema/config、数量、大小及超时校验。FormatRegistry.initialize/verifyBundledResources 仍明确拒绝失败；失败不会替换完整目录，后续调用可重试。isInitialized 仅表示 rawfile 验证成功，真实 Native 路线继续要求该验证、配置状态和原生发布证据。RegistryUi 仅让浏览及演示使用完整生成目录，不把校验失败标记为成功。

完整格式为 PDF、DOCX、PPTX、XLSX、TXT、MD、JPEG、PNG、WEBP、HEIF、MP3、WAV、FLAC、AAC、M4A、OGG、OPUS、WMA，共 18 种；原 43 条规划路线及其输入约束、意图、保真等级、步骤、优先级、降级说明和确认要求全部保留。

ConversionPlanner 与原已通过版本 48f2bd9 字节一致，保留单文件路线、意图、最低保真等级筛选和快速/均衡/高保真排序。本次没有修改任务调度、保真面板接口、报告、国际化、原生协议、五页导航或真实引擎实现。

生成文件为 142 行，包含完整数据及摘要元数据；紧凑排版不减少任何格式或路线。shared JSON 继续是唯一编辑源，生成器不会覆盖现有引擎实现。当前工作区三份已有未提交文件在修复前备份到 D:/HarmonyOS/migration-backups/harmonyOS-before-format-restore-20260929-210231，相关首页演示状态和 Native 不可用时的演示行为已保留。
