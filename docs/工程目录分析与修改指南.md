## 对上传文字的适用性判断

上传文档是通用 Stage 目录说明，完整原文保存在 reference。其 pages/view/viewmodel/common/utils 分法可作组织建议，实际本项目额外有 C++、本地 so 类型包及 shared 配置，不能只按普通 ArkTS 示例搬文件。

响应式断点属于 ArkUI 布局/媒体查询等页面实现，不是 build-profile.json5 的布局参数。只有入口页面需要按实际导航方案使用 @Entry，可复用组件不加 @Entry。文件读取通过用户授权 Picker 和受控副本，上传文字中的网络请求示例不适用于本离线应用；不能照例添加 INTERNET 或全存储扫描权限。

建议修改顺序是：确认需求与能力边界 → 在相应模型/JSON/适配器中修改 → 生成一致类型与配置 → 配置及迁移检查 → DevEco/Hvigor 构建 → 设备和真实文件验证 → 再开放能力与更新文档。
