# 变更提案：文件授权与输入管理

2026-09-29 更新：原背景描述的是变更前状态。用户已批准兼容方案，当前 ArkTS 文件管理与提交入口完成，设备验收待执行；Native 会话/工作区仍占位，不能宣称已打通真实执行。详见 implementation-review.md 和 tasks.md。

## 业务意图

当前应用所有转换均为演示模式（DemoTask），不读取用户真实文件、不生成转换结果。根本原因是缺少**文件授权与输入管理**子系统——从用户选择文件到 Native 层获得可操作的文件句柄的完整链路不存在。

本变更打通这条链路，使应用能够：
1. 用户通过系统 Picker 选择源文件
2. 获取授权的文件 URI 并安全拷贝到应用沙箱
3. 创建 Session/Workspace 供 Native 层使用
4. 将授权文件信息传递给 NativeBridge，为后续真实引擎接入奠定基础

完成后，应用从"纯演示"升级为"可选文件但引擎仍为占位"的中间态，为 P0 的真实引擎接入扫清前置依赖。

## 为什么是当前最优先

| 因素 | 分析 |
|------|------|
| 阻塞关系 | 真实引擎（P0）的输入是 AuthorizedFile + Session，没有这个子系统引擎无从调用 |
| 用户价值 | 当前用户无法选择任何文件，这是最明显的功能缺口 |
| 设计文档要求 | V1.0 方案第 4-5 节明确要求"授权文件管理"作为 NativeBridge 的前置 |
| 复杂度可控 | 不涉及 C++ 引擎实现，纯 ArkTS + HarmonyOS Picker API，复杂度中等 |
| 独立可验证 | 完成后可通过 UI 选择文件→查看授权信息→验证沙箱拷贝，不依赖引擎 |

## 范围边界

### 包含
- 系统文件 Picker 集成（photoAccessHelper / filePicker）
- 授权文件 URI 管理（FileAuthorizationService）
- 安全沙箱拷贝（受控副本，校验大小/类型）
- Session/Workspace 生命周期管理
- ConverterPage 集成：从演示模式切换到"选择真实文件"模式
- 预览器降级：Picker 不可用时回退到演示模式

### 不包含
- 真实转换引擎实现（下一变更）
- 输出文件导出到用户可见目录（下一变更）
- 任务持久化（独立变更）
- 翻译功能（用户构想，暂不规划）

## 成功标准

1. 用户在 ConverterPage 点击"选择文件"，系统 Picker 弹出
2. 选择文件后显示文件名、大小、格式检测结果
3. 文件被安全拷贝到应用沙箱临时目录
4. 本地受控 Session/Workspace 创建，提交调用实际 NativeBridge.initializeSession/registerWorkspace；当前占位失败必须如实展示，不伪造 Native 句柄
5. 预览器下 Picker 不可用时，自动回退到演示模式，不崩溃
6. 新增代码通过 ArkTS 编译与宿主验证；独立编辑器、Previewer 和设备验收在可用环境中另行完成
